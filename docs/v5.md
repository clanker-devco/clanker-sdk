# V5 uses the V4 format

Import `Clanker` from `clanker-sdk/v5`. Use the V4 calls, token fields, and result checks where the Tax contracts support them.
Keep the V3 and V4 clients for existing tokens.
Version 5 requires viem 2.49.3 or newer. We checked its types by hand with TypeScript 5.9 and 6.0 for this release.

| Difference | V5 behavior |
| --- | --- |
| `chainId` | A token with no `chainId` follows the client chain. |
| `buyFee`, `sellFee` | Each defaults to 1%. Each includes the protocol fee. |
| `fee`, `fees` | Rejected: the same number has a different meaning on V4. |
| `vanity` | Accepts true or false with no effect. V5 always mines the required `cccc` suffix. |
| `salt` | Rejected. Each preparation uses a fresh salt. |
| `devBuy.amountOutMin` | Zero or omission means unset. A nonzero value is rejected; use `minAmountOut` for final tokens. |
| `rewards.recipients` | One to seven slots, with positive basis points (bps) that total 10,000. Use `Paired` or omit `token`. |
| `getTokenRewards` | Returns `token`, `poolId`, `rewardBps`, `rewardAdmins`, and `rewardRecipients`. V5 has no V4 position identifiers. |
| Market cap | V5 has no per-launch start price or market cap input. The factory sets the start price for each quote. The V4 market cap helpers do not apply. |
| Address book | `clankerConfigFor` and `CLANKERS` have no V5 entry. Use `TAX_ADDRESSES` from `clanker-sdk/v5`. |
| Types | Import `ClankerTokenV5` from `clanker-sdk/v5`, not from the package root. |
| Unsupported inputs | Vaults, airdrops, presales, positions, presets, custom ticks, sniper fees, lockers, pool extensions, and `Both` or `Clanker` fee preferences remain rejected. |

## Deploy

`wallet` and `publicClient` must use the same chain.

```ts
import { Clanker } from 'clanker-sdk/v5';

const clanker = new Clanker({ wallet, publicClient });
const { txHash, waitForTransaction, error } = await clanker.deploy({
  name: 'Example',
  symbol: 'EXAMPLE',
  devBuy: { ethAmount: 0.01 },
});
if (error) throw error;
const result = await waitForTransaction();
if (result.error) throw result.error;
console.log(txHash, result.address, result.poolId);
```

`deploy` returns `txHash`, `expectedAddress`, `waitForTransaction`, and an optional `transferTxHash` or `error`.
A failure before submission returns `{ error }`. Reads, salt search, closed launches, and simulation failures follow this rule.
`waitForTransaction` returns `{ address, poolId }` or `{ error }`.
An `error.data.type` of `state` means that the launch failed on chain. A type of `unknown` means that the receipt read failed, so the launch can exist. Do not launch again before you check the transaction.
Each management write returns `{ txHash, error: undefined }` or `{ txHash: undefined, error }`.
Errors use `ClankerError` and preserve the real reason. Missing clients and invalid token configs still throw.
`deploySimulate(token, accountOrOptions?)` accepts a V4 `Account` or V5 options and returns the viem simulation result or `{ error }`.

For an unsigned call, use `getDeployTransaction(token, { account: callerAddress })`.
Submit its `address`, `abi`, `functionName`, `args`, and `value` with that caller.
This method sends nothing. The caller must send any recipient transfer themselves after the launch, with `transferLaunchBuy` or an ERC-20 transfer.

The builder reads the factory configuration at one block and sets `expectedConfigVersion`.
The deadline is 1,200 seconds, or 300 seconds with a dev buy. Set `deadlineSeconds` to change it.
The local salt search permits 1,000,000 attempts. `maxTries` limits attempts; `signal` cancels the search.
Each preparation can produce a different token address.

## Dev buy

Warning: a dev buy uses an upgradeable swap router. A low `minAmountOut` gives little price protection.
By default, the SDK simulates the exact launch with a minimum of `1n`, checks the token address, and reads the third result value.
It subtracts `devBuySlippagePercent` with integer math and rounds down. The default is 5%; the value must be above 0 and below 50.
A zero minimum produces an error. An explicit positive `minAmountOut` skips this quote simulation.
The final deployment still simulates the protected call before submission.

`ethAmount` uses native currency units. Use decimal strings for small amounts.
`minAmountOut` uses final token base units with 18 decimals.
V4 `amountOutMin` names the ETH to pair step; V5 has no such input.

With default addresses, the SDK selects `directNativeSwapXRoute` for a native quote.
For a stable quote in the table below, it selects `stableSwapXRoute(publicClient)`: one V3 pool from the native coin to the stable quote, then the Tax pool.
The helper reads the adapter limits and factory pool; it does not search pools.
The minimum protects the final tokens.
Warning: in a sandwich trade, the native coin to stable step can lose more value than the slippage percent.
Set a lower `devBuySlippagePercent` for a large buy.
Warning: a small pool gives a low price for a large buy, and the slippage percent starts from that low price. The BNB Chain pool held about 4,000 USDC on 5 November 2026.
On Arc, the default quote is USDC `0x3600000000000000000000000000000000000000`, and the SDK selects `directArcUsdcSwapXRoute`.
The adapter converts native USDC units from 18 decimals to 6 decimals.
Use at most six decimals in `ethAmount`. The Arc router accepts deadlines no more than 300 seconds ahead.
Other quotes or custom `addresses` require `devBuy.routeData` or `buildBuyRoute`.
The callback receives the predicted token, adapter, hook, quote, amounts, and `poolKey`.
When the SDK sets the minimum, the callback receives `minAmountOut: 1n`. Do not use that value as a limit in the route.

An all-zero `poolKey` means unset. Another key must pair the native coin or its wrapped token with the stable quote, in either order, with zero hooks.
The helper uses its `fee` to select the V3 pool. Its `tickSpacing` must match that fee in the V3 factory.
A fee above `maxExternalPoolFee`, a missing pool, another pair, another tick spacing, or nonzero hooks produces an error.
A native quote does not need `poolKey`. Do not combine a nonzero key with `routeData` or `buildBuyRoute`.

The effective recipient is `devBuy.recipient`, then a nonzero `tokenAdmin`, then the caller.
The contract sends tokens to the caller. If the effective recipient differs, `deploy` waits and transfers the exact bought amount.
It waits for the transfer receipt and returns `transferTxHash`.
If the transfer fails, it keeps the launch result and any transfer hash. The error includes the failure reason.
`failedStep` names the failed step. With `launchReceipt`, the SDK sent no transfer. With `transfer`, the launch succeeded and the transfer failed.
Warning: a second call sends the amount again if the wallet still holds enough tokens.
Check the recipient balance before a retry.
Use the complete `transferLaunchBuy({ txHash, token, recipient })` call from the error to retry.
Without an explicit recipient, `transferLaunchBuy` uses the original creator from the event.
Set `token` when a receipt contains multiple launch buys. Transfers carry no tax.
Without a dev buy, or when the caller receives the tokens, `deploy` does not wait for the launch receipt.

## Rewards and metadata

Use `claimRewards({ token, rewardRecipient })` and `availableRewards({ token, rewardRecipient })`.
For a launch token, the currency is its pool quote. For the burn address `0x000000000000000000000000000000000000dEaD`, it is the launch token itself.
The wrapped token of the native coin maps to native currency; other tokens remain their own currency.
The escrow keeps one balance per recipient and currency. A claim pays that whole balance, across all pools.

Use `getTokenRewards({ token })` to read the reward arrays.
Each slot returns its stored `slot.recipient` and `slot.admin`, including the creator slot.
Use `updateRewardRecipient({ token, rewardIndex, newRecipient })` and `updateRewardAdmin({ token, rewardIndex, newAdmin })` for ordinary slots.
The hook pays `slot.recipient`; `updateRewardRecipient` uses `setCreatorFeeRecipient` for the creator slot.
Its admin follows creator rights. `updateRewardAdmin` rejects that slot and names `proposeCreatorRightsTransfer`.
Prior credits stay with the prior recipient.

Use `updateImage({ token, newImage })` and `updateMetadata({ token, metadata })` for the corresponding extra metadata keys.
These writes and the reward writes have matching `get…Transaction` and `…Simulate` methods. Simulations accept an optional V4 `Account`.
The reward reads have matching `get…Transaction` methods.

V5 also has `predictToken`, `configVersion`, `creatorRights`, `quoteConfig`, `dividendOf`, and `withdrawableDividends`.
Use `withdrawDividends` for holder dividends; `paid = false` returns `{ error }` without a transaction.
Use `claimTo` for the caller's escrow credits and `setCreatorFeeRecipient` for creator fees.
Creator rights use `proposeCreatorRightsTransfer`, `acceptCreatorRightsTransfer`, and `cancelCreatorRightsTransfer`.
Metadata methods include `updateTokenContractURI`, `updateTokenExtraMetadata`, `updateTokenName`, and `updateTokenSymbol`.
Each V5 write has a matching `get…Transaction` method. The package exports all eight suite ABIs.

## Chains and token fields

| Chain | Chain id | Native quote | Stable quote | V3 pool fee for a stable dev buy |
| --- | --- | --- | --- | --- |
| Base | 8453 | ETH | USDC (6 decimals) | 0.05% |
| BNB Chain | 56 | BNB | USDC (18 decimals) | 0.01% |
| Monad | 143 | MON | USDC (6 decimals) | 0.3% |
| X Layer | 196 | OKB | USDC (6 decimals) | 0.05% |
| Robinhood Chain | 4663 | ETH | USDG (6 decimals) | 0.01% |
| Arc | 5042 | none: the native coin is USDC | USDC (6 decimals), the default | none: no V3 step |
| Ethereum | 1 | ETH | USDC (6 decimals) | none: no creator buy |
| Arbitrum | 42161 | ETH | USDC (6 decimals) | none: no creator buy |
| Unichain | 130 | ETH | USDC (6 decimals) | none: no creator buy |

These chains apply when launches are open.
Ethereum, Arbitrum, and Unichain have no launch-buy adapter. A launch with `devBuy` gives an error before the salt search. A launch without `devBuy` works.
Omit `addresses` for the default deployment. Other deployments require the relevant `TaxAddresses` fields.
V3 and V4 reject new launches on every chain, including `startPresale`. Existing token management stays unchanged.

`tokenAdmin` selects the creator; zero or omission selects the caller.
`pool.pairedToken` defaults to native currency. The `WETH` string also means native currency. On Arc, both mean USDC. Other quote addresses require factory approval.
`image`, `metadata`, and `context` keep their V4 fields. Context defaults to `{ interface: 'SDK' }`.
`contractURI` defaults to empty text; `metadataEditable` and `antiSnipeEnabled` default to true.
The factory controls the initial anti-snipe fee. Its supply goes to the pool; read `launchSupply` for the amount.
Optional `burn`, `dividends.share`, and `integrator.share` divide the tax after the protocol share and must total at most 100%.
The creator receives the remainder. `dividends.minimumHolding` uses token base units and must meet the factory policy and supply bounds.
The first reward with the creator as admin becomes the creator slot. Omit rewards to create one creator slot.

## CLI

```sh
clanker-sdk deploy --name "Example" --symbol "EX" --chain base
```

Buy and sell fees default to 1%. Only name and symbol are required.
If you omit one of them, the CLI asks for the main launch options. The flags that you set preselect those options, and an option that you deselect does not apply. With both, it asks nothing and uses the flags.
In text mode, the CLI prints the configuration before it simulates or sends. `--json` mode prints no summary.
Use `--dev-buy-eth` and optional `--dev-buy-slippage`; the native, stable, and Arc USDC quotes use SDK routes.
`--dry-run` simulates without a transaction. A failed simulation exits with code 1.
A recipient transfer prints its hash.
Exit code 1 means that the launch failed or that nothing was sent.
Exit code 2 means that the launch exists or can exist, and that a step after the send failed:
- If the launch succeeds and the transfer fails or does not start, the CLI prints the token, `transferError`, and a `warning`.
- If the CLI cannot read the launch receipt, it prints the transaction hash, the predicted token, and `launchState: unknown`.

Warning: do not run the command again after exit code 2, because that can launch a second token. Check the transaction. Then send the tokens from the launching wallet, or use `transferLaunchBuy` in the SDK.
The prompts do not ask for reward recipients. Use `--reward-recipients` with a JSON array of one to seven slots, with `Paired` or no `token`.
`deploy` launches V5 tokens only. A chain without V5, for example `base-sepolia`, gives an error. The V4 launch flags are removed.
Use these flags to allocate the tax:

```sh
clanker-sdk deploy --name "Example" --symbol "EX" --chain base \
  --burn 10 --dividend-share 20 --dividend-min-holding 10000 \
  --integrator 0x4444444444444444444444444444444444444444 --integrator-share 5
```

`--dividend-min-holding` requires `--dividend-share` and accepts whole tokens. Its default is 10000 tokens.
The CLI converts whole tokens to base units with 18 decimals.
Set `--integrator` and `--integrator-share` together.
`deploy` does not prompt in `--json` mode.

The `rewards` and `token` commands work on V5 tokens and select the client for each token.
For `rewards claim` and `rewards available`, `--token` accepts a reward currency or a V5 launch token.
V5 launch tokens select V5 automatically. Plain currencies use V4 unless you add `--v5`.
Use `--v5` to claim or check V5 rewards for USDC, WETH, or the zero address.
The flag produces an error on chains without a V5 entry.
The `vault` and `airdrop` commands are for V4 tokens.
